# moodhair · Personal Stylist Studio

사진 한 장으로 주변 8가지 헤어스타일과 가장 어울리는 스타일을 제안하는 React 앱입니다. 중앙은 업로드한 원본을 그대로 표시하며, 주변 이미지는 AI가 만든 3×3 보드에서 각 칸을 보여줍니다. 얼굴 보존 및 칸 경계는 생성 모델의 정확도에 따라 달라질 수 있습니다.

## 실행

Node.js 22 이상에서:

```sh
npm install
cp .env.example .env
# .env에 운영자의 GEMINI_API_KEY 설정
npm run server
# 별도 터미널
npm start
```

프런트엔드: http://localhost:3000, API: http://localhost:3001. API 키는 서버 전용이며 사용자는 키나 개인정보를 입력하지 않습니다. Google Gemini 이미지 편집 사용 권한 및 과금 가능한 API 계정이 필요합니다. 키가 없으면 실제 생성 대신 연결 안내를 표시합니다.

```sh
npm run build
npm run server
```

프로덕션은 Node 서버가 dist와 API를 함께 제공합니다. 정적 GitHub Pages만으로는 생성 기능이 작동하지 않습니다. 공개 배포 전에는 호스팅 계층에서 요청 제한과 비용 한도를 적용하세요. 기본 서버는 동시 생성을 2건으로 제한합니다.

## 개인정보 처리

- 이름, 연락처, 생년월일, 회원가입 없음.
- 선택 시 브라우저에서 이미지 재인코딩하여 EXIF 등 원본 파일 메타데이터를 제거합니다.
- 사진 선택만으로는 전송하지 않습니다. 전송 안내가 표시된 생성 버튼을 누르면 사진을 앱 서버와 Google Gemini API로 전송합니다. 추가 질문이나 동의 체크박스는 없습니다.
- 공유 전에는 사진과 결과를 저장하지 않습니다. 공유 링크 생성에 동의하면 원본을 중앙에 합성한 보드와 추천 내용을 저장합니다. 링크를 아는 누구나 7일 동안 볼 수 있습니다. 만료된 링크는 접근을 차단하고 조회 시 저장 객체를 삭제합니다. 화면 지우기는 이미 생성한 공유 링크를 삭제하지 않습니다.
- 외부 AI 서비스 보관 정책은 별도 적용됩니다. https://ai.google.dev/gemini-api/terms
- 저장 버튼은 원본 사진을 정확히 중앙에 합성한 JPG를 사용자 기기에 다운로드합니다.
- AI 추천은 미적 제안이며 실제 미용 시술 결과를 보장하지 않습니다.

검증: `npm test -- --run`, `npm run build`.

## 미리보기 환경

`npm run dev` 한 번으로 화면(3000)과 API(3001)를 함께 실행합니다. Codespaces에서는 Ports의 **Moodhair Preview (3000)** 를 열면 됩니다. API는 화면 서버의 프록시로 연결되므로 3001 포트를 공개할 필요가 없습니다. 컨테이너에 다시 연결하면 자동 실행됩니다.

배포 빌드 확인은 `npm run preview`로 실행합니다. 같은 3000 포트를 사용하므로 개발 서버를 먼저 종료하세요. `.env`의 API 키가 없어도 화면과 사진 선택은 확인할 수 있으며, 생성 시 설정 안내가 표시됩니다.

## 공개 홈페이지

로그인 없이 사진 선택 → 생성 버튼 한 번으로 8가지 스타일과 추천 결과를 생성합니다. 사진의 AI 전송 안내는 버튼 위에 표시하며 API 키는 서버의 비밀 설정에서만 사용합니다.

## 결과 다운로드와 공유

- 전체 3×3 보드와 선택한 스타일을 각각 JPG로 다운로드합니다.
- 공유 링크를 받은 사람은 같은 보드·추천 이유를 열고 다운로드할 수 있습니다. 원본 얼굴 사진이 포함됨을 링크 생성 전에 안내합니다.
- 링크 복사로 카카오톡 대화, 인스타그램 DM, 스토리의 링크 스티커 등에 붙여넣습니다. 앱으로 공유 버튼은 Web Share API를 사용하며 지원 앱과 동작은 기기·브라우저에 따라 달라집니다. 특정 앱으로 직접 전송하거나 자동 게시하지 않습니다.
- 운영 환경은 Sites가 연결하는 R2 `BUCKET`에 저장합니다. Node 개발 서버는 Git에서 제외한 `.local-shares/`에 저장하며 서버 재시작 후에도 링크를 유지합니다. 만료 후 물리적 정리를 위해 운영 저장소의 `shares/` 접두사에 수명 주기 정책을 추가할 수 있습니다.
